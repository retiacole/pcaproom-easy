# pcaproom-easy v0.3.0

[English README](README.en.md) | 日本語

**[すぐにやってみる](https://retiacole.github.io/pcaproom-easy/)** · [オフライン用HTML](https://github.com/retiacole/pcaproom-easy/blob/main/pcaproom-easy.html)

<img src="docs/images/pcaproom-character.png" align="right" width="120" alt="白と青の衣装で杖と本を持つpcaproom-easyのキャラクター">

**パケットを読み、通信の根拠を見つける。**<br>
*Read packets. Follow the evidence.*

パケットを開き、詳細を読み、根拠を選んで答えるネットワーク入門教材です。Wireshark風の画面で、基本プロトコルを51問・95設問で練習します。

<br clear="right">

## 日本語・英語の切り替え

HTML上部の **Language** メニューから **日本語 / English** を選べます。51問すべての問題文、選択肢、3段階ヒント、解説、用語帳、操作案内に対応しています。言語はブラウザに保存され、次回も同じ言語で開きます（保存が利用できる場合）。

学習途中でも切り替えられます。回答、根拠、選択中の設問・パケット・詳細項目、入力途中のフィルター、時刻表示、ヒントの利用状況、獲得済みフラグを保ちます。パケットのバイト列、解析値、回答の値、フィルター構文は共通で、進捗JSONは日本語・英語間で共用できます。言語設定は `pcaproom-easy.language.v1`、進捗は従来の `pcaproom-easy.progress.v1` に別々に保存します。

## はじめ方

1. [すぐにやってみる](https://retiacole.github.io/pcaproom-easy/) を開きます。オフラインで使う場合は、[オフライン用HTML](https://github.com/retiacole/pcaproom-easy/blob/main/pcaproom-easy.html) の右上にある「Download raw file」で保存し、保存したHTMLをブラウザで開きます。リポジトリの「Code → Download ZIP」で全体を保存・展開しても使えます。
2. 「最初のパケットを開く」から始めます。学習マップのどの章からでも選べます。
3. パケット一覧のNo.を押して詳細を読み、「① 回答」に答えを入力・選択します。
4. 「② 根拠を追加」がある設問は、根拠も必須です。「根拠を選ぶ」で **Packet Details** に移動し、答えを読み取った詳細行をクリックします。選んだ行の近くに出る「この行を設問1の根拠に追加」（番号は現在の設問）を押してください。行を選んだだけでは追加されません。
5. 回答欄に追加した根拠のパケット番号・項目名・値が表示されたら、回答と根拠を答え合わせします。複数設問がある問題は、すべて正解すると1フラグです。

インストール・サーバーの準備・アカウント登録は不要です。オンライン版はページを開くだけで始められます。保存したHTMLはインターネット接続なしで利用できます。JavaScriptとdialog要素に対応したブラウザが必要です。

## 内容

| 区分 | 内容 | 問題数 |
| --- | --- | --- |
| 操作 | 一覧・詳細・根拠選択、表示フィルター | 6 |
| 基礎プロトコル | Ethernet、ARP、IPv4/IPv6、ICMP、ICMPv6/NDP、UDP | 18 |
| 通信を読む | TCP、DNS、DHCPv4、NTP、HTTP、TLS | 18 |
| 卒業調査 | 端末の接続、通信できない理由、Webアクセスと観測限界 | 3 |
| 実物で役立つ読み方 | TCP Options・生の番号、EDNS/DHCP追加情報、時刻と最小フレーム | 3 |
| 背景通信を含む卒業調査 | 284パケットからDNS・TCP接続・GETを絞り、HTTP応答を調査 | 3 |

各章3問、17章で51問です。12のプロトコルテーマと操作2章、卒業調査1章、実践2章を含みます。ガイド付き→練習→自力で確認と進みます。IPv6のRA、DHCPv6/SLAAC、QUIC/HTTP/3などは用語帳にも補足しています。DHCPv6やQUICそのもののパケット問題は初版に含みません。

全問に3段階ヒントと答え・解説があります。1問100ポイント、合計51フラグ・5100ポイントです。時間制限、誤答やヒントによる減点はありません。解説を見ただけではクリアせず、実際に回答と根拠をそろえる必要があります。復習で回答を書き換えても、正答時の記録を保存して獲得済みフラグを保ちます。

## 画面の機能

- パケット一覧とプロトコル別詳細。基本項目表示と全項目表示を切り替えられます。
- TCPのOptionsを展開してMSS・SACK Permitted・Window Scale・Timestampsを確認できます。
- 相対時刻・絶対時刻（UTC）・前フレームとの差を切替。差分は表示フィルター適用前の記録順です。
- 選択フィールド名をステータス欄に表示。「この項目で絞る」で条件を入力欄に作れます。バイト列など値の比較が未対応の型は、その項目の存在条件を作ります。
- フィールドを選ぶと、対応する16進数バイトを強調します。解析で生成・再構成したフィールドには、その旨を表示します。
- 表示フィルター、対応構文の早見表、元の表示への解除。
- TCPストリームの追跡。方向ごとにシーケンス順で再構成し、再送を重複させません。
- 回答、根拠選択、複数パケット選択、順序指定、フィルター問題。
- 同じ教材を本物のWiresharkで確認できるPCAP保存。各章末の任意ステップで、同じフィルターを適用して残るNo.を比較します。
- 用語帳、ヒント・解説、進捗保存・読込。

### フィルターの範囲

プロトコル・フィールドの存在、`==`、`!=`、`>`、`<`、`>=`、`<=`、`contains`、`&&`/`and`、`||`/`or`、`!`/`not`、かっこに対応します。代表例は `dns`、`udp`、`ip.addr == 10.0.0.10`、`tcp.flags.syn == 1`、`tcp.stream == 1`、`frame contains "GET"` です。

`frame contains "GET"` は、各フレームの収録バイト列に対する大小文字を区別する検索です。文字列はUTF-8で比較し、再構成済みの文字列や暗号化前の本文を検索するものではありません。この教材の `frame contains` は二重引用符付きの文字列に対応します。

Wiresharkの全フィルター機能を再実装したものではありません。正規表現、集合、CIDR、関数、フィールド同士の比較などは未対応です。不正な構文はエラーを表示し、直前の適用済み表示を保持します。フィルター問題は適用結果で採点し、意味が同じ条件式を受け付けます。

## 保存と復元

v0.1の既存45問の回答値・根拠・完了記録を維持しています。旧版の進捗JSONも読み込めます。追加6問は未クリアで始まります。

自動保存キーは `pcaproom-easy.progress.v1` です。ほかのroomの保存領域は読み書きしません。配布場所やファイルの保存場所、ブラウザが変わると保存領域が別になる場合があります。移行には進捗JSONを使ってください。

ローカルHTMLでの自動保存はブラウザによって扱いが異なります。保存できない場合は画面に案内します。「保存」でJSONを残しておけば、HTMLの移動やブラウザ変更後も「読込」で復元できます。読込では変更内容を確認し、現在の進捗をバックアップしてから置き換えます。確認でキャンセルした場合や、ファイルが不正な場合は現在の進捗を変更しません。

## 教材データと観測範囲

45個の合成PCAP、537フレームを同梱します。すべて架空のアドレス・名前・通信内容です。実際の端末操作、ネットワーク通信、ライブキャプチャは行いません。任意PCAPの読込機能はありません。

ビルド時に実PCAPバイトを生成し、tsharkで解析したフィールド・表示・位置をHTMLに埋め込みます。プレイ時にtsharkは必要ありません。教材とPCAPの対応を維持するため、表示用の値を手作業で別に作る方式ではありません。

背景通信のある共有キャプチャには、ARP・mDNS・SSDP・ICMPv6/NDP・別端末のDHCP設定・NTPを270パケット収録し、調査対象のDNSとHTTP接続をその間に配置しています。表示フィルター章の末尾からも、この調査へ進めます。

TLSは構造を読むための合成データです。特に不透明なApplication Dataは実セッションの暗号文を再現したものではなく、その点を教材内に明記しています。SNIが常に見えるとは扱いません。TLS ClientHelloはTLS 1.2の小さな構造例を維持し、現実のClientHelloはより長く、多くの暗号スイート・拡張があることを課題文に補足しています。DNS応答、ping成功、HTTP応答コードだけで接続成功・サービス正常・攻撃を断定しない問題を含みます。

### パケットと時刻の扱い

- 通常のTCP例はSYNでMSS・SACK Permitted・Window Scale・Timestampsを提示します。MSSなどの有無は実環境で異なります。両方向のSYNでTimestampsに合意した後は、RSTを除くセグメントにも付けます。生シーケンス番号は再生成しても同じ32bit値とし、相対番号とACKの対応を保ちます。
- 通常のDNSにはEDNS0のOPTを追加。mDNSでは省略します。DHCPには端末識別情報、最大メッセージサイズ、更新・再バインド時間を含めます。
- 遠隔応答のTTL、ルーターのNAフラグ、Windows風32バイトEchoペイロード、HTTPヘッダーを整えています。ペイロードだけでOSを断定する教材ではありません。
- MACアドレスは架空のローカル管理アドレスです。実物のWiresharkでは設定によりベンダー名が表示されます。
- 同梱の解析表示はUTC・Cロケールに固定。WiresharkのArrival Timeは設定によりローカル時刻にもなります。ログとの照合ではUTCに合わせてください。表示文字列はWiresharkの版でも変わるため、教材の正答・根拠はフィールド値で扱います。
- 通常はEthernet最小60バイト（FCSを除く）までパディングします。比較問題だけはOptionsを省き、送信処理内で得た54バイトとLAN上の60バイトを組み合わせた教材であることを明示しています。

TCP仕様の参考：[RFC 9293（MSS）](https://www.rfc-editor.org/rfc/rfc9293.html)、[RFC 7323（Window Scale・Timestamps）](https://www.rfc-editor.org/rfc/rfc7323.html)。

## ソースからのビルド

開発時に必要なもの：Node.js 22以上、Python 3（標準ライブラリのみ）、tshark。検証したtsharkは4.6.7です。

```sh
npm run build
```

既定の実行ファイルはPython `/usr/bin/python3`、tshark `/usr/local/bin/tshark` です。異なる環境では `PCAPROOM_PYTHON` と `PCAPROOM_TSHARK` に実行ファイルのパスを指定してください。Wiresharkのユーザー設定・TLS鍵設定は読み込まず、一時プロファイルで解析します。`TZ=UTC`・`LC_ALL=C`を指定して、ビルド機のタイムゾーンやロケールの影響を除きます。

- `content/`：教材・問題・正答・パケット仕様。`en.js` は英語の表示文だけを保持し、ビルド時に翻訳の不足や正答データへの上書きを検証します。
- `packet-tools.js`：実PCAP生成・TCP再構成
- `decode-pcap.py`：tsharkのPDMLからフィールド抽出
- `src/engine.js`：表示フィルター・採点・進捗検証
- `src/app.js` / `src/style.css` / `src/shell.html`：画面
- `src/i18n.js`：表示の翻訳、言語設定、元データを保つ英語表示
- `src/data.js` / `captures/` / `pcaproom-easy.html`：ビルド結果
- `tests/`：パケット・採点・DOM操作のテスト

## 検証

```sh
npm install
npm test
```

テスト時だけjsdomを使います。プレイ用HTMLには外部パッケージを読み込む処理はありません。既存のjsdomを使う場合は `PCAPROOM_JSDOM_MODULE` でモジュールのパスを指定できます。`PCAPROOM_HTML` にHTMLのパスを指定すると、DOMテストはその配布ファイル自体を検証します。

自動テストで、パケット生成・チェックサム、日本語・英語それぞれ全51問・95設問の画面操作、正答・誤答・根拠、全フラグ獲得、旧版進捗の互換性、保存・再開、時刻切替、読込確認、PCAP出力、ストリーム再構成を検証しています。新しい3つのフィルター課題は実際のtsharkと残るフレーム番号が一致すること、異なるタイムゾーン・ロケールで同じPCAPの解析結果が一致することも確認しています。

項目から生成するIP・MAC・文字列・数値フィルターとICMPエラー内のUDP検索は、実際のtsharkと結果を比較します。パケット選択・時刻変更・言語切り替え時の一覧スクロール位置も検証します。

言語切り替え時の入力・進捗維持、英語表示の翻訳漏れ（アクセシビリティ用ラベルを含む）、言語設定の再読込、自動保存が利用できない場合も検証します。DOMテストは実際のブラウザ描画やダウンロードUIを検証するものではありません。
